# 0006. 채점 실행부를 인터페이스로 추상화한다

상태: 채택 (2026-11-06, 기획서 v0.6)

## 맥락

운영에서는 채점을 K8s Job으로 돌린다(T1). 그런데 클러스터는 크레딧 때문에 12월 초에나 만들고, 그 전 사전 기간에 "제출 → 채점 → 결과"를 로컬에서 관통해야 한다. 로컬에는 Docker만 있다. 실행 방식이 둘인데 격리 요구(M5)는 같다.

## 결정

judge-worker에 `JudgeRunner` 인터페이스를 두고 구현을 둘 만든다. `DockerRunner`는 로컬에서 호스트 Docker로 컨테이너를 띄우고, `KubernetesRunner`는 운영에서 Job을 만들어 완료를 기다린 뒤 표준 출력과 종료 상태를 회수하고 지운다. 어느 쪽을 쓸지는 프로파일로 고른다. 두 구현 모두 M5의 격리 항목을 똑같이 강제한다.

## 결과

- 클러스터 없이 로컬에서 채점 파이프라인 전체를 개발하고 테스트한다. 12/1 전 사전 기간이 가능해진다.
- 채점 쪽은 실행 이미지와 실행 명령만 등록하면 다른 언어도 돌릴 수 있다. 다만 허용 요소 검사(lint-worker)는 Python `ast` 전용이라 언어를 늘리려면 파서가 따로 필요하다. 기획서가 Python만 다루기로 한 이유다.
- 감수할 것: 구현이 둘이라 같은 동작을 두 번 유지한다. 격리 수단이 달라서(`--network none` vs NetworkPolicy, `--pids-limit` vs 노드 풀 설정) 동일성은 코드가 아니라 공격 코드 5종 테스트로 보장한다.
- 감수할 것: 로컬에서 judge-worker가 컨테이너 안에서 호스트 Docker 소켓을 쓰는 구조(Docker-outside-of-Docker)라 bind mount 경로가 호스트 기준이어야 하고, 소켓 권한은 호스트 root와 같다. 로컬 한정으로 받아들인다(`docs/architecture.md` §5).
