# 0012. 메시지 브로커는 클러스터 밖(학교 AWS EC2)에 둔다

상태: 채택 (2026-11-09. 학교 AWS 계정에서 보안 그룹 인바운드 규칙을 팀이 직접 추가할 수 있음을 조교에게 확인)

## 맥락

0002에서 RabbitMQ를 골랐고 처음에는 AKS 서비스 노드에 올릴 계획이었다. 두 가지가 걸렸다.

- 크레딧 때문에 AKS를 쓰지 않을 때 `az aks stop`으로 내린다(0010). 브로커가 클러스터 안에 있으면 내리는 순간 큐에 남은 메시지가 사라지거나, 지키려면 PV를 붙여 관리해야 한다. DB를 밖에 둔 이유(0005)와 같은 문제다.
- 서비스 노드는 4 GiB에서 kubelet 예약을 빼면 3 GB가 안 된다(0008). Spring 앱 두 개와 RabbitMQ(quorum 큐)를 같이 올리면 빠듯하다.

학과에서 팀별 AWS 계정을 준다. 조건은 서울 리전만, Route 53(도메인)과 공인 인증서 기반 HTTPS는 제공하지 않음(공인 인증서를 받을 도메인이 없다는 뜻), EIP는 인스턴스 ID로 요청하면 조교가 붙여 준다, 보안 그룹 인바운드 규칙은 팀이 직접 추가할 수 있다.

## 결정

RabbitMQ를 학교 AWS EC2 1대에 docker compose로 띄운다. 운영의 core-api·judge-worker·lint-worker는 AKS에서 이 브로커에 AMQPS(5671, TLS)로 붙는다. 로컬 개발은 그대로 compose의 RabbitMQ를 쓴다.

- compose 파일은 `infra/ec2/docker-compose.yml`에 커밋한다. EC2는 Terraform 밖이라 재현 기록이 필요하다.
- EIP를 붙여 브로커 주소를 고정한다. AKS 쪽 Secret에는 이 IP를 넣는다.
- TLS는 **자체 서명 CA**로 한다. 도메인을 쓸 수 없어 공인 인증서를 받을 수 없다. CA가 EIP를 SAN으로 넣은 서버 인증서를 발급하고, CA 인증서를 세 서비스에 K8s Secret으로 배포해 트러스트스토어로 쓴다.
- 관리 플러그인도 같은 자체 서명 CA로 TLS를 켠다(`management.ssl.port = 15671`). 평문 15672는 열지 않는다.
- 보안 그룹: 5671(AMQPS)과 15671(관리 API)은 **AKS 아웃바운드 공인 IP만** 허용한다. 15671은 ADMIN-01(큐 적재량)을 위해 core-api가 읽는 용도다. 팀원이 관리 UI를 볼 때는 포트를 열지 않고 SSH 터널(`ssh -L 15672:localhost:15672`)로 들어간다.
- 큐는 durable, 메시지는 persistent로 둔다. 브로커가 재시작돼도 메시지가 남는다.
- 세팅은 B가 맡는다.

## 결과

- AKS를 내렸다 올려도 큐의 메시지가 남는다. 클러스터를 다른 구독에 다시 만들어도 브로커 주소(EIP)는 그대로다. 0005·0011과 같은 "Azure 구독 상태와 무관한 곳에 둔다" 원칙이다.
- 서비스 노드에서 RabbitMQ 메모리가 빠진다.
- 감수할 것: AKS 아웃바운드 IP는 Standard LB의 관리형 공인 IP라 클러스터를 다시 만들면 바뀐다(0008). 바뀔 때마다 보안 그룹 두 규칙을 갱신해야 한다. 고정 공인 IP를 미리 만들어 AKS 아웃바운드에 지정하는 방법은 EC2 세팅 이슈에서 검토한다.
- 감수할 것: 자체 서명 CA라 인증서 발급·갱신과 CA 배포를 우리가 관리한다. 유효기간은 프로젝트 기간을 넉넉히 넘기게 잡는다.
- 감수할 것: 관리 API는 TLS여도 Basic 인증이라, 모니터링 전용 계정(읽기 권한만)을 따로 만들고 허용 IP를 AKS 아웃바운드 하나로 좁힌다. KEDA의 rate 모드(0002)도 같은 경로를 쓴다.
- 감수할 것: Azure(koreacentral)와 AWS(ap-northeast-2) 사이를 메시지가 오간다. 둘 다 서울이라 지연은 작지만, 두 클라우드 중 한쪽 네트워크가 막히면 채점이 멈춘다. EC2 1대라 단일 장애점인 것은 0002와 같다.
- 감수할 것: 학과 계정은 수업이 끝나면 회수될 수 있다. 브로커에는 장기 보존 데이터가 없고 처리 중인 메시지만 있어 영향이 작다. DB를 여기 두지 않는 이유이기도 하다(0005).
- 감수할 것: 로컬(평문 5672)과 운영(TLS 5671)의 연결 설정이 달라진다. 프로파일별 설정(`spring.rabbitmq.ssl.enabled` 등)으로 나눈다.
