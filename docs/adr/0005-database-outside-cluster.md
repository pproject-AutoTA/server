# 0005. DB는 클러스터 밖(Supabase PostgreSQL)에 둔다

상태: 채택 (2026-11-06, 기획서 v0.6)

## 맥락

Azure 크레딧이 한정돼 있어 클러스터를 쓰지 않을 때 내리고, 크레딧이 떨어지면 팀원 구독으로 옮겨 다시 만들 수 있다. 클러스터 안에 DB를 두면 내리고 올릴 때마다 PV·백업·이전을 챙겨야 한다. 시연 한 번을 위해 그 부담을 질 이유가 없다.

## 결정

PostgreSQL은 Supabase 관리형을 쓰고 클러스터 밖에 둔다. 로컬 개발은 docker compose의 postgres를 쓴다. 트랙 산출물 "DB 덤프"는 시연 전 `pg_dump`로 떠서 `sql/`에 넣는다.

연결은 **공유 풀러 세션 모드(포트 5432)**로 한다. 직접 연결은 Free 플랜에서 IPv6 전용이라 IPv4만 쓰는 AKS 아웃바운드와 대부분의 로컬 네트워크에서는 붙지 않는다. 트랜잭션 모드(포트 6543)는 prepared statement와 세션 상태(advisory lock 포함)를 지원하지 않아 Flyway 같은 마이그레이션 도구가 깨진다.

## 결과

- 클러스터를 지우고 다시 만들어도, 다른 구독으로 옮겨도 데이터가 그대로다.
- DB 운영(백업, 패치, 디스크)을 직접 하지 않는다.
- 감수할 것: Free 플랜은 1주일 미사용 시 정지된다. 주 2회 상태 확인 쿼리를 돌리고 `pg_dump` 백업을 둔다(기획서 리스크 표).
- 감수할 것: 세션 모드는 연결 하나가 풀러 연결 하나를 점유한다. 앱의 커넥션 풀 크기를 Supabase 풀러 한도 안으로 맞춘다.
- 감수할 것: 로컬 compose postgres와 Supabase의 PostgreSQL **메이저 버전을 맞춘다**. 다르면 로컬에서 되던 SQL이 운영에서 깨질 수 있다.
- 감수할 것: 로컬과 운영의 DB가 달라 스키마 적용 방식을 하나로 맞춰야 한다. Flyway 도입을 검토 중이다(A 영역).
